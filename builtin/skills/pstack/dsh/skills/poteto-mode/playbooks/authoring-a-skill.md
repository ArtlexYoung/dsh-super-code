### Authoring or modifying a Skill

1. Follow the bundled `authoring.md` guide in this adapted package. Inspect an existing Skill before replacing it.
2. Validate frontmatter, description, invocation choice and every relative resource link. Project/user overrides use the native DSH roots; the bundled package remains read-only.
3. Run relevant structural/behavior tests for procedural changes; get user feedback for subjective preferences.
4. Report the concrete diff and evidence. Follow the Opening a PR playbook only if PR creation is authorized; otherwise leave a reviewable local result.

Reply with the Skill path, design decisions, actual validation and any unresolved limits.
