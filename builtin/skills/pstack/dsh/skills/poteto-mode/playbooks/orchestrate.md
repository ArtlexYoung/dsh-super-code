### Orchestrate

Run a standing program through scoped owners, independent verification and a durable task-local tracker. The coordinator owns the queue and verdicts; owners write the code. One task driven to a predicate uses Autonomous run instead. A request for a plan does not authorize execution or publication.

1. Record units, dependencies, exact base/head commits, output paths, acceptance evidence and permission boundaries in the project plan. Start with one unit and take it through owner, verification and authorized handoff/merge before widening the queue.
2. Assign one owner per branch/PR and one isolated worktree or non-overlapping file set per writer. Only that owner writes, pushes, rebases or retargets its branch, under the user's authorization. The coordinator sends code fixes, rebases and conflicts to the owner. Changing a base affects its dependents; do it only after reviewing that dependency frontier. Preserve unrelated branches and changes.
3. Use a fresh worker for each independent task. Its kickoff includes the goal, allowed and forbidden paths/effects, exact evidence with pass predicate, resource paths and the full upstream reports it depends on; siblings cannot see each other. Resume the same worker only for a follow-up on the same task. Transfer a built state through a complete, verified handoff or a supported fork; do not assume the host can fork runtimes. Default to inherited models; apply only exposed, confirmed choices.
4. The root owns a bounded queue and every dependent dispatch. Replace upstream sub-coordinators with area queue entries and rollups at DSH's depth limit; a child returns the requested next role instead of spawning grandchildren. Start the next ready unit as capacity opens. Inspect the kickoff/evidence contract when a unit fails rather than copying the same bad brief across the program.
5. Give each stabilized unit a verifier that did not author it. Prefer a confirmed different model family; disclose same-model independent review or missing independent delegation. Check actual behavior, artifacts, diffs and receipts; green CI or a summary alone is insufficient. A verdict names one head SHA, and a new head needs new verification. Return scope drift to its owner and park unrelated improvements.
6. Use actual DSH completion notifications and agent-control tools. Inspect available worker side effects and current forge state before reporting, using authenticated read-only queries rather than stale summaries. Do useful independent work; when only waiting remains, yield. Do not send a status message that restarts an idle worker or claim a subscription the host lacks.
7. Diagnose a stalled worker before retrying: reduce scope after a context/capacity limit, retry an unchanged brief after a confirmed transport failure, or select another confirmed route when a model-specific error warrants it. Respect host retry ownership. After two failed worker replacements for the same unit, drop/replan that unit and record why. Quiesce an old writer before its replacement writes. Check late results against the current head and give any unique findings to the active owner; never overwrite current work with an obsolete result.
8. Advance dependencies only on verified units. Owners publish/merge only within explicit authorization; otherwise stop that unit at verified local or merge-ready. Ask only for an essential product decision, missing approval or a blocker that survived replanning. Account for every worker as completed, replaced, absorbed, blocked or still running. Checkpoint queue, IDs, evidence, pending decisions and the exact next dispatch if the host cannot continue unattended.

Reply with completed units against the goal, live PR states/verdicts and links when PRs exist, current verified heads, dropped work with reasons, pending decisions and the concrete resume point.
