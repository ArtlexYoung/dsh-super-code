# 评测结果

中文 · [English](en/EvaluationResults.md)

## 评测设计

### 题集

SWE-bench Pro hard-100（固定标识 `swebench-pro-hard-100-ddd22492f1c38839`），使用官方评分器。

- 「hard-100」是本项目按既有难度方法选出的 100 题，并非官方认定的最难 100 题。
- 调优仅使用 SWE-bench dev 中筛选的 33 道有效困难题。hard-100 只用于评测冻结后的候选版本和排查问题，**不参与调优**，以避免对评测题过拟合。
- 所有成绩均已纳入后续复核（见[评分更正](#评分更正)），每组均有 100 题有效评分。

### 对照

对照选用官方标准预设，而非 minimal。旧宿主实测中，标准 + high 通过 51 题，minimal + high 通过 46 题，且标准每题 token 少 23.5%。与更强的对照比较，结论更严格。

### 控制变量

同一组对比中，宿主、模型、思考等级和预算保持一致，仅替换 Agent 预设。宿主或模型变化时，单独列出并说明。

### 评测过程

1. **旧宿主基线**：在 DSH `0.1.5-rc.2` 与 `deepseek-v4.1-flash` 上评测官方各预设和插件各版本，Super Code `0.3.0` 候选通过 56 题，高于官方最好的标准 + high（51 题）。
2. **宿主升级后效果下降**：升级至 DSH `0.2.1-rc.2` 与 `deepseek-v4.1-flash-1017` 后，默认预算下标准降至 46 题，Super Code `0.3.4` 降至 41 题，低于标准。
3. **定位原因**：宿主探针显示新版收紧了上下文预算（见[旧预算的内容](#旧预算的内容)），由此判断预算是退化原因之一。
4. **恢复旧预算后复测**：双方均改用旧预算。标准仍为 46 题；Super Code `0.3.5` 提升至 49 题。据此，`0.3.6` 起插件默认使用旧预算。
5. **跨模型验证**：在 `glm-5.3-flash` 上与原生 ZCode 对比，检验方案是否依赖特定模型。

## 结论

| 对比 | 结果 |
|---|---|
| 新宿主，均为旧预算：Super Code `0.3.5` vs 标准 + high | 49 vs 46；净耗时 -21.3%，token -34.6%，模型调用 -25.5% |
| 新宿主，默认预算 → 旧预算 | Super Code 41 → 49；标准 46 → 46 |
| 旧宿主：Super Code `0.3.0` 候选 vs 官方最好的标准 + high | 56 vs 51 |
| 旧宿主：Super Code `0.3.0` 候选 vs minimal + high | 56 vs 46；耗时 -47.6%，token -44.9% |
| GLM-5.3-flash：Super Code `0.3.4` vs 原生 ZCode | 45 vs 29；耗时 -37.1%，token +52.4% |

- **标准**：改用旧预算后通过数不变，token 增加 14.2%。逐题统计新通过 7 题、回退 7 题。
- **Super Code**：改用旧预算后多通过 8 题，token 仅增加 0.4%，净耗时减少 19.4%。逐题统计新通过 12 题、回退 4 题。
- 两组插件版本不同（0.3.4 → 0.3.5），收益不能全部归因于预算。
- 旧预算插件组实际为 `0.3.5` 加显式预算覆盖。`0.3.6` 起默认使用该预算，但**未**对 0.3.6 ~ 0.3.8 重新运行 100 题评测。
- 标准的旧预算组仅覆盖宿主预算，未加载 Super Code。

### 旧预算的内容

恢复 `0.1.5-rc.2` 时期的上下文策略：按完整窗口计算，用量达到 80% 时开始压缩，保留最近 16% 的原文，摘要上限 8,192 token，压缩追加和溢出重试各 1 次；新版宿主的 PTC 默认和最大时限设为 600 秒。以上各项同时恢复，并非单参数实验。[配置方法](UsageGuide.md#运行预算)

[宿主探针](../eval/results/swebench-pro-final-100/HostBudgetDiagnostics.json)固定 1,000,000 token 窗口、384,000 输出预留，测得：

| | 旧版 | 新版 |
|---|---:|---:|
| 压缩阈值 | 800,000 | 550,464 |
| 保留原文 | 160,000 | 98,560 |
| 摘要请求上限 | 8,192 | 65,536 |

两版摘要指令相同。探针使用确定性摘要，不评估摘要质量，也不能证明每道题都触发了上述变化。

### 新版组合的退化

与旧宿主、旧模型相比，标准由 51 题降至 46 题，Super Code 由 0.3.0 候选的 56 题降至 0.3.4 的 41 题。期间宿主、模型和插件同时变化。预算是已定位的原因之一，但不能证明全部退化均由预算导致。

同一道题在不同轮次中结果可能不同。由于各轮配置也在变化，现有数据尚不足以估计固定配置下的随机波动。

## 口径

- **净耗时**：扣除最终有效作答中的失败请求和重试等待，不含评分。
- **原始耗时**（历史版本表）：最终有效作答的 Web RPC 耗时，不含评分、镜像下载和复评，但未扣除内部失败请求和重试。中位数取第 50、51 项均值，P90 取第 90 项。0.0.9 旧文档记为 16.27 分钟，按统一口径为 16.458。
- **调用次数**：排除已记录的失败请求。
- **token**：总 token = 缓存输入 + 非缓存输入 + 输出，输出含思考内容。缓存率 = 全部缓存输入 / 全部输入（非逐题平均）。先逐题合计，再按有效题数平均。
- **缺失用量不估算**，因此 token 不等同于完整账单，也不含此前被放弃的尝试。
- **执行方式**：DSH 使用原生 Web RPC，ZCode 使用完整原生 CLI。
- **隐私**：公开数据仅保留核对所需字段，不含私有提供方地址、凭证、环境配置、本机路径或用户消息原文。逐题结果文件保留在仓库中，不包含在 npm 包内。
