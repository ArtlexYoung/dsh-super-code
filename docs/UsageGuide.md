## 模型

插件不单独配置模型。已有可用模型时直接使用；若没有，请在 Harness「设置 → 模型」中添加提供方，再在输入框下方选择模型和推理等级。

子 Agent 默认使用父 Agent 的模型。权限和工具由 Harness 管理。

## 找不到预设

请先确认插件已启用，再对照[兼容性](Compatibility.md)核实宿主版本，然后按宿主版本处理：

**Harness 0.1.7 及以后（声明式预设）**：预设由插件声明、宿主加载。请在「设置 → Super Code 模式」中点击「安装预设」。宿主未开放管理接口时，页面会直接提示。

**Harness 0.1.5 / 0.1.6（目录预设）**：插件首次加载时会自动安装一份用户预设。若未出现，请在「设置 → Super Code 模式」中手动安装。

- 默认标识符 `super-code` 被占用时，可改用其他标识符，原有预设不会被覆盖。
- 主动删除该副本后，重启不会自动重新安装，需要再次手动安装。

插件 0.2.0 以前，设置入口位于「插件 → 插件配置」。

## 设置页

「设置 → Super Code 模式」包含五个标签页：

| 标签页 | 内容 |
|---|---|
| 首页 | 预设状态与版本、删除保护等级、MCP 开关、在线与历史对话数 |
| 预设配置 | 安装、重装、重命名 |
| 上下文配置 | [运行预算](#运行预算) |
| 删除保护 | [删除保护](#删除保护) |
| 连接 | [MCP 连接](#mcp-连接) |

切换标签页不会丢失未保存的输入。

### 名称与语言

- 标识符用于选择预设；显示名称可单独修改，支持中文和空格，最多 120 字。
- 默认名称和描述跟随 Harness 的中英文设置。用户修改过的字段，插件不会改动。
- 切换语言只影响显示字段，不改变预设内容和版本。
- 旧版 Harness 会缓存预设列表，因此文案变化后页面会自动刷新一次。
- 同一宿主的预设文件只能使用一种语言，多个客户端无法同时显示不同语言。
- 安装目录只读或 YAML 无法安全识别时可能同步失败，可在设置页刷新后重试。

## 预设版本与重装

设置页分别显示**插件版本**和**预设版本**。

- 两者一致：表示预设与已安装的插件同步，不代表 npm 上没有更新版本。
- 旧预设未记录版本：显示「未记录版本」，不视为最新。
- 插件升级不会自动更新已安装的预设。如需使用新预设，请重新安装。

**重装流程**：点击「重新安装预设」→ 确认框列出将被替换的预设及新名称、标识符 → 核对后确认。

- 可从列表中移除条目，但不能在列表清空后确认。取消或按 Esc 不会产生任何改动。
- 重装会覆盖旧预设内容，请先自行备份自定义内容。
- 已有会话继续使用旧预设，新会话使用新预设。

**安全措施**：

- 只替换能够核实由本插件安装的预设（目录式核对安装记录、UUID、路径和目录身份；声明式核对来源标记或安装记录）。未标记的旧副本和同名声明不会被改动。
- 旧内容备份在 `.super-code-backup-*`：目录式位于用户预设根目录下，声明式位于当前 profile 下（安装记录为 `.super-code-presets.json`）。
- 安装失败时自动恢复；进程意外中断时，可从备份手动恢复。

## 侧边栏

在右侧边栏选择「Super Code」，三个部分互斥展开，默认展开任务；点击当前标题可全部收起。切换后保留阅读位置、筛选条件和草稿。界面跟随 Harness 的中英文设置。

### 任务

只读，展示会话中已有的记录：

- **目标**：已记录的任务目标；未记录时显示用户原话。
- **步骤**：模型记录的待办事项，显示「已完成/总数」。没有步骤时不会生成计划或进度。
- **工具调用**：按工具汇总成功、失败与运行状态。
- **文件**：已成功执行、且能从工具参数或 diff 确认的文件改动，包括 PTC 中的嵌套调用。

注意事项：

- 运行停止不等于任务完成。
- 文件列表并非完整的 Git diff：终端或外部脚本造成的间接修改可能未被记录；历史改动也不代表文件当前仍有差异。失败、未完成、只读操作以及子 Agent 继承的历史均不计入。
- 列表全部展开并采用虚拟滚动，长列表也能流畅显示。超出显示上限时会提示，完整内容可在详情中查看。
- 不修改提示词、模型请求或工具定义，也不向模型上下文写入内容。

### 协作执行

Agent 执行树，显示每个 Agent 的状态、用量和缓存率。

- 拖动空白处可平移，使用滚轮或按钮可缩放。
- 点击节点会在侧边栏新标签页中打开详情，主对话不切换。
- 详情按对话展示：用户任务、Agent 回复、可展开的工具调用及结果。顶部显示状态、Token 和缓存，展开「详情」可查看更多用量、任务记录和记忆使用记录。
- 运行动画遵循系统的「减少动态效果」设置。

[任务](images/task-status.png)和[执行树截图](images/agent-tree.png)使用当前插件、官方前端组件及演示数据渲染，仅展示界面，不代表模型效果。

### 记忆库

先选择「当前项目」或「全局偏好」，再按主题浏览或搜索（主题、摘要、标识符），点击条目可查看详情和来源。支持新增、编辑和删除（需确认）。手动修改的条目标记为「手动维护」，只保留当前内容，不保留版本历史。

记忆分为三层：

| 层级 | 内容 | 范围 |
|---|---|---|
| 任务状态 | 当前目标、约束、进展、验证记录 | 当前会话 |
| 项目记忆 | 有来源的项目事实、经验和约定 | 同一工作区路径，按主题划分 |
| 全局偏好 | 用户明确要求跨项目遵守的偏好 | 同一 Harness 存储目录 |

- 如需长期保留某项约定，可直接告知 Agent。是否保存成功，以工具返回成功且记忆库中可见为准。
- Agent 保存项目记忆时必须关联真实的工具结果；保存全局偏好时必须有用户原话和跨项目意图。
- 不同路径的项目或 Git worktree 不共享项目记忆。
- 记忆保存在本机宿主中，不写入项目文件，也不会整库发送给模型。每次最多自动带入当前主题的 4 条摘要（≤2 KiB）和全局偏好的 4 条摘要（≤1 KiB），详情需由 Agent 主动读取。
- 记忆不能覆盖当前指令，不能用于授权，也不能证明代码仍与记录时一致。
- 历史会话的记忆可直接查看，无需恢复 Agent 或调用模型。

### Agent 的记忆使用记录

在执行树中点击节点 → 展开「详情」→ 展开「记忆使用记录」。记录区分带入上下文、读取摘要、读取详情、保存和删除，点击记录可跳转到记忆库中的对应条目。

- 这是宿主记录的动作，不代表模型已理解或遵守。
- 子 Agent 继承的父会话历史不计为其自身的读取；失败的调用不计为成功读取。
- 最多显示最近 100 条，完整记录见会话日志。
- 条目之后被修改或删除时，记录仍保留，但记忆库只显示当前内容。

## 批量工具调用

Super Code 使用 Harness 原生 PTC：在一次模型调用中组合多个工具操作，例如同时读取多个互不相关的文件，获得结果后再决定下一步。无需另选模式。

- 相互独立的读取并行执行；写入、测试、状态变更和存在依赖的步骤按顺序执行。
- 部分失败时保留成功的结果，只重试失败或过期的读取。
- 插件声明自身任务和记忆工具中可并行的动作，未识别的动作默认不并行。其他工具以其在 Harness 中的声明为准。
- 权限确认、取消和结果保存由宿主管理。

批量调用减少的是模型与工具之间的往返次数，不保证每个操作都更快。

## 运行预算

位于「上下文配置」标签页。插件默认已使用效果更好的旧预算，通常无需修改。括号内显示宿主自身的默认值，便于对比。

| 类型 | 包含 | 作用范围 |
|---|---|---|
| 通用预算 | 压缩比例、摘要上限、PTC 时限、重试次数 | 默认仅 Super Code；开启「同时应用到官方预设」后也作用于标准、PTC、极简和创造预设 |
| Super Code 专属 | 活跃任务记录上限、任务记忆容量 | 仅 Super Code |

- 「同时应用到官方预设」默认关闭，只修改预算，不修改官方预设的工具和提示词，也不影响自定义预设。
- 保存后对新建的 Agent 生效，运行中的 Agent 不受影响，也不会重启。
- 留空即使用插件默认值；「恢复默认」会清除界面上的覆盖值。
- 保存失败时保留输入；若提示预算已在别处修改，请先重新读取。
- 旧宿主没有 `ptcRuntime` 时，PTC 时限输入框不可用，其他预算仍可设置。

插件默认值如下（无需手动写入配置，仅填写需要修改的项）：

```yaml
budgets:
  pressureBasis: window      # 按完整上下文窗口计算；host 表示沿用宿主策略
  thresholdRatio: 0.8        # 用量达到 80% 时开始压缩
  retainRatio: 0.16          # 保留最近 16% 的原文，必须小于 thresholdRatio
  summaryMaxTokens: 8192     # 摘要上限
  compactionRetries: 1       # 压缩追加尝试次数
  maxOverflowRetries: 1      # 溢出重试次数
  ptcTimeoutMs: 600000       # PTC 默认时限（毫秒，含工具等待）
  ptcMaxTimeoutMs: 600000    # PTC 时限上限，不超过宿主上限
applyToOfficialPresets: false
maxTasks: 32                 # Super Code：活跃任务记录数
maxContextBytes: 32768       # Super Code：任务记忆上下文字节数
```

- 调用中显式指定的更短时限仍然有效。
- 旧宿主的 PTC 按 CPU 忙碌时间计时，新宿主按总耗时计时，两者不可直接比较。
- 调大 `maxTasks`、`maxContextBytes` 会占用更多上下文，一般保持默认即可。

## 删除保护

位于「删除保护」标签页，默认为**宽松**模式。

| 模式 | 行为 |
|---|---|
| 关闭 | 不提示，不拦截 |
| 宽松（默认） | 提示 Agent 删除时默认使用可恢复的 `trash`，脚本中同样适用。用户明确要求使用 `rm` 时允许使用，插件不再二次确认 |
| 严格 | 脚本中也不允许直接使用 `rm`。识别到永久删除命令时，每次都需用户确认，仅放行临时文件或构建产物的清理 |

宽松模式提供给 Agent 的规则原文：**删除文件或目录默认用 `trash <path>`（可恢复）；仅清理临时文件、构建产物且我已确认时才用 `rm`。**

- 默认仅保护 Super Code。「同时应用到官方预设」默认关闭（与预算中的同名开关相互独立）。
- 保存后对之后的命令生效。
- 旧配置 `true` 视为严格，`false` 视为关闭。

严格模式在终端命令执行前检查 `rm`、常见包装命令、内联 shell 脚本和 PowerShell 删除命令（如 `Remove-Item`），PTC 中的终端调用同样检查。

- 只有用户同意宿主弹出的一次性确认后才会放行；拒绝、取消或出错均会拦截。每次确认仅对当次有效。
- 没有 `trash` 时，Agent 应改用其他可恢复的方式或停止操作。
- 它不是系统沙箱：不检查外部脚本文件、混淆过的程序或各语言的删除 API。如需进程级隔离，请使用宿主沙箱。

宽松模式仅通过提示引导，不拦截命令，宿主原有的权限检查照常生效。

## MCP 连接

允许外部 MCP 客户端（如其他 AI 编码工具）将任务委派给 DSH 执行。默认关闭，仅监听本机 `127.0.0.1`，使用 Streamable HTTP 和凭证认证。

### 开启

在「连接」标签页中：

1. 勾选允许的工作目录（含子目录）。
2. 按需修改端口和最大连接数。
3. 打开开关。修改会自动保存。

「允许 MCP 新增对话」默认开启；关闭后只能明确复用已有对话。新对话归入已有工作区，目录尚未登记时创建无后缀的同名工作区，标题以 `[MCP]` 开头。

「允许调用方审批」默认关闭。开启后，指定 MCP 任务的一次工具审批可交给调用方，通过交互表单或 `dsh_approve` 决定；宿主权限策略和目录申请的用户确认保持有效。

目录说明：

- 每次进入连接页都会重新读取 DSH 工作区。首次配置时会预选已有工作区，之后新增的工作区**不会**自动获得授权。
- 可通过目录选择器添加目录。取消勾选即撤销授权；取消最后一个目录会同时关闭 MCP。

连接数说明：

- 最大连接数默认为 3，最多 32，同时也是任务并发上限。
- 可在连接页断开客户端；空闲 10 分钟后自动断开。断开不会取消已接收的任务。
- 首页的「在线对话」表示关联的 MCP 连接仍在线，与任务是否完成无关；断开后计为历史对话。

端口冲突时会直接报错。地址以页面显示为准。

### 配置客户端

1. 复制连接页中的「连接 Prompt」，提供给支持 Streamable HTTP MCP 的客户端。其中包含地址、认证方式和工具说明，**不含**真实凭证。
2. 单独复制凭证，在客户端中配置为 `Authorization: Bearer <凭证>`。请勿将凭证写入仓库或共享的提示词。
3. 保持 DSH 运行。更换凭证后旧凭证立即失效，请同步更新客户端。

客户端能否根据提示词自动配置 MCP 取决于客户端本身，也可手动填写地址和认证信息。凭证在连接页默认展开，离开页面后隐藏。

### 工具

| 工具 | 用途 |
|---|---|
| `dsh_status` | 查看允许目录、开关、连接与任务额度、阻塞任务和恢复提示 |
| `dsh_models` | 查询模型与思考强度 ID，供 `dsh_run`、`dsh_send` 指定；省略时沿用会话当前或默认选择 |
| `dsh_read` | 分页读取所属会话及受管子会话的公开消息、工具结果与失败详情，不返回推理和私有配置 |
| `dsh_approve` | 仅在允许调用方审批时，批准或拒绝一个精确的待审批操作，仅生效一次 |
| `dsh_sessions` | 连接后应首先调用：按目录列出最近的对话、状态、是否可复用，以及连接额度和任务并发占用 |
| `dsh_run` | 发起任务。传入 `taskId` 复用指定对话；传入 `newConversation: true` 新建对话（两者均未传入时也新建）。**不会**自动复用最新对话。同一 `requestId` 搭配相同输入不会重复提交，输入不同则报冲突 |
| `dsh_wait` | 查询任务状态、输出、工作区变化和新事件，最多等待 30 秒。未传入任务 ID 时分页列出所有任务 |
| `dsh_send` | 在同一对话中补充要求或继续执行，需使用新的 `requestId`。不会代为批准权限 |
| `dsh_request_directory` | 申请新的工作目录，需用户在 DSH 中批准 |
| `dsh_cancel` | 请求取消对话及其子任务。之后应继续查询状态，确认任务已实际停止 |

### 申请新目录

客户端调用 `dsh_request_directory`，并提供 `requestId`、已存在的绝对路径 `path` 和理由 `reason`。DSH 会弹出全局确认框（无需打开设置），显示客户端名称、目录和理由。

- 只有用户点击「允许访问」后才会授权，模型的自动审批无法替代。
- 使用相同输入重复调用可查询状态：`pending` / `approved` / `rejected` / `expired`。
- 批准前不能在该目录发起任务。
- 最多 8 个待审批请求，5 分钟后过期。拒绝、关闭服务或重启均不会自动授权。
- 客户端名称和理由由客户端自行填写，仅供参考。

### 任务状态与恢复

- 任务使用会话当前或明确指定的模型、Super Code 预设和用户的权限设置，不会自动放行权限。模型与思考强度选择保留在该会话中。
- 客户端的沙箱不会延续到 DSH。允许目录只控制能否在该目录发起任务，并非文件沙箱。
- 同一工作区的任务不并行执行。如需并行，请自行准备独立的 worktree，插件不会创建、删除或合并 worktree。
- `waiting_confirmation`：仅开启调用方审批且存在对应请求时可由调用方处理，否则由用户在 DSH 中确认。
- `finished`：执行已结束，但 `acceptance` 始终为 `not-verified`，结果是否正确需由调用方自行验证。
- 返回的文件信息是对 Git 工作区的观察结果，包括任务开始前已有的改动，不能证明全部由本任务产生。非 Git 目录或超出观察上限时标记为不可用。
- 等待超时或客户端断线均不会取消任务。关闭连接仅表示不再接收新请求。
- 重启后不会自动重新发送提示词。请通过 `dsh_sessions` 或任务列表找回任务 ID，确认状态后再明确继续。无法确认状态时显示 `interrupted` 或 `unavailable`；未确认停止的任务会继续占用并发额度。

遇到上限时，保留原 `requestId` 和输入，通过 `dsh_status`、`dsh_wait` 等待空位，不要取消其他客户端的任务或改动提供服务的 DSH 应用。结束 SDK 会话时，先调用 `transport.terminateSession()` 发送 DELETE，再关闭客户端；仅 `client.close()` 不会释放服务端额度。没有原生 MCP 工具时可使用包内 `super-code-mcp` 命令，JSON 参数从标准输入读取，凭证由私密环境变量 `DSH_MCP_TOKEN` 提供。

### 存储与上限

- 任务记录、配置和凭证保存在当前 profile 的 `super-code-connection` 目录中，目录权限为 0700，文件权限为 0600。每个 profile 只能运行一个服务实例。
- 上限：200 条任务记录、每个任务 128 次补充、最近 200 条事件、输出保留最后 12,000 字符。目录申请历史最多 100 条，仅保存在内存中。
- 任务记录已满时会明确拒绝新任务，不会自动删除旧记录。

## 前端 Skill

插件内置 `super-code-frontend`，用于页面、组件、视觉调整、响应式布局、交互状态和浏览器验证。重点检查：

- 元素是否对齐到同一基准线
- 可见范围与可点击范围是否一致
- 控件位置是否稳定，操作距离和输入负担是否合理

它沿用项目自身的视觉风格，不限定框架，也不新增工具。平时只向模型提供名称和简介，任务匹配时才加载正文和相关参考。也可在请求中直接说明「用 super-code-frontend」。

- 0.3.3 起新安装或重装的预设才包含该 Skill。已有预设请先备份自定义内容，再重新安装。
- 项目或用户目录中存在同名 Skill 时，按宿主优先级覆盖内置版本。
- 浏览器验证部分仅为方法指导，不强制防止循环，也不会自动写入长期记忆。
- 能否提升前端成品质量需通过单独的实际任务评测验证，安装测试和 SWE 成绩无法证明这一点。
