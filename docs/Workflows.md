# 工作流

在会话顶部打开「工作流」，可浏览随插件提供的四套 Skill。默认关闭的包仍显示在目录中；需要使用时，在「设置 → Super Code 模式 → 预置 Skill」启用对应包，并选用允许 Skill 的会话预设。

推荐路线覆盖需求澄清、规格实现、故障诊断、调研设计、持续开发、代码整理和界面设计。选择一个步骤，可以查看真实 Skill 名称、用途、内容结构、版本和来源。全部 Skill 也可以按包、关键词、收藏或最近使用筛选；每页最多展示 24 项。

「放入对话草稿」把真实的 `/skill-name` 放在草稿开头，保留已有文字，并返回对话。检查后由你发送。含附件、引用或正在发送的草稿会暂时禁止插入。若项目或其他包覆盖了同名 Skill，页面会说明来源冲突，并禁止从该内置条目调用。

「开始此路线」和「确认本步完成」用于记录你确认过的进度，不代表 AI 已经执行或验证成功。收藏、最近使用和各会话进度只保存在当前浏览器；清除浏览器数据后无法恢复，也不会同步到另一设备。

代码工作台的「所有操作」集中提供保存、查找、Git、设置等现有操作和已打开的文件。按 `Ctrl+Shift+P`（macOS 为 `Cmd+Shift+P`）打开，输入关键词，用上下方向键选择，按 Enter 执行，按 Escape 关闭。文件旁会显示未保存状态，不能执行的操作保持禁用。

## 自动维护内置资源

维护命令在源码仓库运行，需要 Node.js 22 或更新版本、npm、Git 和已登录的 GitHub CLI。先安装开发依赖。

```sh
npm run updates:check
npm run updates:apply -- --branch chore/bundled-updates
# 只处理指定包或依赖
npm run updates:apply -- --branch chore/oil-and-marked --only oil-ui,dependencies:marked
```

维护环境第一次安装依赖时可运行 `npm run updates:install`。它按锁文件使用项目原有的 DSH 测试版本，安装时暂时匹配开发用的 peer 声明，完成或失败后恢复公开的宿主兼容范围；不使用忽略 peer 冲突的安装选项。更新过程也会核对 DSH 依赖版本没有改变。

检查命令生成报告，不修改产品文件。应用命令要求当前工作区干净，在独立工作区创建指定本地分支；更新、构建、类型检查、测试和分发检查全部通过后，才创建本地提交。命令不推送、不合并，也不发布。再次从同一基线运行时，会复用干净的维护分支，对已更新的内容不再提交。

四个 Skill 包使用固定来源、固定提交和文件摘要。只下载需要分发且本地内容不同的文件；不执行上游安装器。oil-ui 保留插件内置版本的适配，不恢复其独立更新脚本。npm 默认只选择兼容版本，并检查新增或变化的直接及间接依赖许可证、来源、完整性和安装脚本；宿主兼容版本不参与通用升级。

需要适配的目标会列入报告，其他可更新的 Skill 或依赖继续处理。PStack 的 DSH 转换器锁定已审查版本；其升级需要同步检查宿主覆盖文件。OpenSpec 的 Skill 与 CLI 必须匹配，跨主版本需要单独适配。构建或测试失败时不创建提交，保留候选工作区和日志供排查；不会自动覆盖其中的修改。如果进程被强制结束，先检查候选与报告，再处理报错所指的残留锁。

报告默认位于 `.development/updates/run-*/report.json`，也可以通过 `--report` 指定位置。报告含本地工作区位置，不应直接作为公开文档上传。

仓库附带每周一次的 GitHub Actions 检查配置。将代码合入默认分支后才会进入定时调度；默认只检查。仓库变量 `SUPER_CODE_AUTO_UPDATE=true` 会启用自动更新，或在手动触发时勾选 `apply`。启用后，通过验证的结果推送到 `chore/bundled-updates-<运行编号>`，不会自动合并或发布；报告保留为该次运行的 artifact。
