# 工作流

在「设置 → Super Code 模式 → 预置 Skill」启用对应包后，会话顶部才会出现它的入口：Matt 工作流、PStack 工作流、OpenSpec。每个入口是独立页面，窗口较窄时可从「更多会话视图」进入；关闭对应开关后隐藏，已经保存的任务与成果继续保留。oil-ui 只出现在 Skill 目录中，没有工作流页面。目录只显示已启用的包。会话预设还需要允许使用 Skill。

三个页面共用便签纸面、手绘感标题和状态标记，再用点缀色和各自的任务布局区分工作方法：

| 页面 | 工作方式 |
| --- | --- |
| Matt · 多任务实现 | 便签任务卡呈现澄清、规格、拆票、实施和复盘；可添加具体任务与依赖，也可以插入原型支线。 |
| Matt · 单会话小任务 | 实现卡占据主要位置，澄清和复盘放在旁边，需要时再打开。 |
| Matt · 故障修复 | 调查档案突出可复现的失败与修复，复核和经验单独排列。 |
| Matt · 复杂探索 | 问题与已确定的决策分栏，验收后进入决策栏；路径清楚后交给规格阶段。 |
| PStack · Feature | 按「理解与定形」「实现与证据」组织任务，所有关注点仍通过 `poteto-mode` 的 Feature 工作流执行。 |
| PStack · Refactoring | 并排查看行为基线、目标结构与迁移证据，通过 `poteto-mode` 的 Refactoring 工作流保持行为一致。 |
| OpenSpec | 按提案、实施、验收归档组织文档卡。 |

作者给出的默认顺序是方法引导，可以直接选择需要的任务。「添加任务」可填写具体目标、产物和使用的 Skill；同一 Skill 可以用于多张任务卡。「按需工具」中的加号会添加支线任务，文字按钮则直接打开 Skill。编辑任务可以调整顺序和前置任务；前置任务尚未验收时，会标为等待，不能设为当前任务或验收。循环依赖会被拒绝，输入保留。修改已验收任务的目标、产物、Skill 或依赖时，会重新打开任务并保留已有成果供复查。每条流程最多 64 张卡。

任务卡可按状态和关键词筛选，卡面显示已保存的成果或阻塞原因。任务有可推进、正在做、等待前置任务、受阻、已验收几种状态；同一流程只设一个当前任务。填写成果说明或关联文件后才能验收，也可以重新打开。工具成功、会话待办完成或 AI 回合结束都不会自动验收任务。

Matt 的跨会话实施按作者方法，每张票使用新上下文；原型有具体疑问时才使用。项目首次使用可通过 `setup-matt-pocock-skills` 配置任务后端和文档位置。PStack 模型设置按需配置，长任务从开始保留决策轨迹；`sharpen` 深化提示词，本身不修改代码。作者方法下可查看条件与原文；委派、远程写入、发布仍服从当前项目和会话授权。

「准备任务指令」将真实 `/skill-name`、目标、产物和已保存的前置成果写入原生草稿，保留已有文字并返回对话，由你检查和发送。同一 Skill 的不同任务会更新自动生成的说明。含附件、引用或正在发送时禁止插入；同名 Skill 被其他项目或包覆盖时，显示来源冲突并禁止调用内置条目。

「会话执行」读取当前任务、下一步、待办、工具操作与文件记录。默认 Super Code 模式也能读取任务工具留下的记录；原生待办是否存在取决于工具配置。工具操作可展开详情，文件可在启用的代码工作台中打开或关联到当前任务。文件操作记录不能代替 Git 差异或内容验收。

各作者页分别恢复上次使用的流程。每个会话、每条流程分别保存任务定义、目标、状态与成果。任务顺序调整后仍按稳定身份保存成果和草稿。切换任务时保留未保存输入；保存一个任务或目标不影响其他草稿；保存失败不会推进状态。刷新恢复保存成功的数据；多个独立页面共享收藏和记录，不会以旧快照覆盖另一页的更新。数据仅在当前浏览器保存，最多保留最近 32 个会话，不跨设备同步。旧记录按任务含义迁移，不虚构产物。

「Skill 目录」支持包筛选、关键词、收藏与最近使用，每页最多 24 项。任务卡是本地工作记录，不会自动建立或同步 GitHub/GitLab 工单、调度 AI、验证文件内容。真正的执行仍由宿主与 Skill 负责。

代码工作台的「所有操作」集中提供保存、查找、Git、设置等现有操作和已打开的文件。按 `Ctrl+Shift+P`（macOS 为 `Cmd+Shift+P`）打开，输入关键词，用上下方向键选择，按 Enter 执行，按 Escape 关闭。文件旁显示未保存状态，不能执行的操作保持禁用。

## 自动维护内置资源

维护命令在源码仓库运行，需要 Node.js 22 或更新版本、npm、Git 和已登录的 GitHub CLI。先安装开发依赖。

```sh
npm run updates:check
npm run updates:apply -- --branch chore/bundled-updates
# 只处理指定包或依赖
npm run updates:apply -- --branch chore/oil-and-marked --only oil-ui,dependencies:marked
```

维护环境第一次安装依赖时可运行 `npm run updates:install`。它按锁文件使用项目原有的 DSH 测试版本，安装时暂时匹配开发用的 peer 声明，完成或失败后恢复公开的宿主兼容范围；不使用忽略 peer 冲突的安装选项。更新过程也会核对 DSH 依赖版本没有改变。

检查命令生成报告，不修改产品文件。应用命令要求当前工作区干净，在独立工作区创建指定本地分支；更新、构建、类型检查、测试和分发检查全部通过后，才创建本地提交。命令不推送、不合并，也不发布。再次从同一基线运行时，会复用干净的维护分支，对已更新的内容不再提交。

四个 Skill 包使用固定来源、固定提交和文件摘要。只下载需要分发且本地内容不同的文件；不执行上游安装器。oil-ui 保留插件内置版本的适配，不恢复其独立更新脚本。npm 默认只选择兼容版本，并检查新增或变化的直接及间接依赖许可证、来源、完整性和安装脚本；宿主兼容版本不参与通用升级。

需要适配的目标会列入报告，其他可更新的 Skill 或依赖继续处理。PStack 的 DSH 转换器锁定已审查版本；其升级需要同步检查宿主覆盖文件。OpenSpec 的 Skill 与 CLI 必须匹配，跨主版本需要单独适配。构建或测试失败时不创建提交，保留候选工作区和日志供排查；不会自动覆盖其中的修改。如果进程被强制结束，先检查候选与报告，再处理报错所指的残留锁。

报告默认位于 `.development/updates/run-*/report.json`，也可以通过 `--report` 指定位置。报告含本地工作区位置，不应直接作为公开文档上传。

仓库附带每周一次的 GitHub Actions 检查配置。将代码合入默认分支后才会进入定时调度；默认只检查。仓库变量 `SUPER_CODE_AUTO_UPDATE=true` 会启用自动更新，或在手动触发时勾选 `apply`。启用后，通过验证的结果推送到 `chore/bundled-updates-<运行编号>`，不会自动合并或发布；报告保留为该次运行的 artifact。
