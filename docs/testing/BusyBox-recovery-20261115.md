# BusyBox 报错后的工具选择补充

2026-11-15 已补充 Windows 模型指引，并完成定向回归和完整 Windows DSH 的真实模型测试。BusyBox 长路径读取失败后，模型可改用原生文件工具；涉及写入的命令失败后，先检查实际结果，再完成剩余操作。

实现沿用 `src/dsh/windows-shell-instructions.ts` 的共享字符串，Super Code 和启用内置 Bash 的官方预设使用同一规则。保留 259 字符工作目录提前选择原生执行器的逻辑，不新增自动命令重放、错误拦截器、依赖或配置项。权限拒绝、取消和远程断连不得通过换工具绕过；单独的“文件不存在”也不当作长路径问题的证明。

真实模型测试使用 Windows 11 ARM64 隔离虚拟机、官方 x64 Desktop `0.2.2-rc.2`，桌面和 Bash 通过系统兼容执行。安装包仍标记 `0.4.1`，是未发布候选；SHA-256 为 `7269eb2a5f557294bfa90e521f785b3392144c5315d1ce5e59190202c7470070`。联网模型由本机隔离代理转发，测试文件位于 Windows 本地目录。

1. **读取补救通过。** 强制先用 BusyBox `cat` 读取 382 字符路径，实际返回退出码 1 和“文件不存在”；模型随后通过原生 `read` 读取同一路径，正确返回文件标记和数字 42。会话实际系统提示包含新增规则。
2. **部分写入补救通过。** 命令先追加一条尝试记录，再执行长路径 `cat` 并重定向输出。读取失败时，追加已完成，原输出已被截断为空。模型先读取这两个文件确认状态，再用原生 `write` 完成复制。独立进程核对源与输出哈希相同，尝试记录只有一条；事件中原 Bash 复合命令只执行一次。
3. **不存在文件处理通过。** 短路径缺失文件的 `cat` 失败后，模型使用原生 `read` 和 `glob` 核对，报告文件不存在，没有生成替代文件。
4. **限权边界通过。** 只读会话中的 Bash 被现有 `SUPER_CODE_BASH_SANDBOX` 检查在执行前拒绝；模型只读核对后报告，没有重试或换原生工具写入，独立检查目标文件不存在。这是限权 Bash 前置拒绝，未将其称为系统文件权限拒绝的测试。

两种预设共享提示、禁用后的提示撤下、非 Windows 不注入，以及原有权限与工具选择由定向组件测试覆盖；本轮真实模型只在 Super Code 预设执行上述四个场景。提示规则引导模型作出后续工具调用，不保证所有模型每次都采用相同行为，也没有修复 BusyBox 二进制的长路径限制或 Windows 远程挂载的原生写入兼容问题。

Windows 测试准备中先后遇到 HTTP 响应为字节数组、配置为 YAML 和插件尚在加载的问题，均按测试驱动的实际错误修正；没有据此修改产品。早期失败不计入通过结果。
