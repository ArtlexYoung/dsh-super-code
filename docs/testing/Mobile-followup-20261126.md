# main 手机交互补验 · 2026-11-26

后续[剩余项目补验](Remaining-acceptance-20261126.md)已确认正式安装后手机插件列表可见，并完成 SSH 网页设置、任务与记忆面板、精简模式审批取消及依赖更新分支流程。下文保留本轮当时的结果。

本轮结论为**部分通过**。dsh-Go 的 SSH、中转，以及 Agents Anywhere 三个通道均完成手机批准、拒绝和长命令取消。AA 全局偏好保存、同轮继续读取及宿主冷重启后读取通过。同 ID 双宿主切换时，对话正文、任务和记忆保持隔离，但 dsh-Go 会显示另一宿主的回合统计；后台返回后的自动恢复也仍不稳定。

被测 main 为 `6d6ae2ebe4dfc93334e1321188f1e85b40f5267a`，版本 `0.4.3`，本轮未修改产品源码或依赖。三个隔离宿主均安装 SHA-256 为 `e53a64e19ce1f28a041af284d17c35b15f509102270349eecf56aa40e38b8bca` 的候选包，各 6165 个普通文件逐一匹配。

客户端为 Android 15/API 35 ARM64 无窗口模拟器，dsh-Go `1.4.0`、Agents Anywhere `2.2.0`。SSH 与中转宿主运行完整 Linux ARM64 Harness `0.2.2-rc.5`，中转插件及服务端为 `0.6.4`；AA 使用原装桥接 `2.2.0-desktop.c4f5dcd2c35c8.r6c2a8ac0` 和完整 Harness `0.2.2-rc.3`。正式操作从手机界面执行，结果通过宿主事件和实际文件独立核对。

同 ID 检查使用两个宿主通过官方接口创建的相同会话 ID。A 的第二次延迟任务完成时，B 的页面已经打开；完成前后的页面均无 A 的迟到回复，B 的真实工具读取也确认任务列表与全局偏好为空。切换到 B 后，回合统计却显示 A 的“2 分钟、9 步、103K tokens”，B 实际该轮用时约 13.9 秒、4 步。重开 App 后恢复为 B 的“14 秒、4 步、47.3K tokens”。这是 dsh-Go `1.4.0` 原生界面的已观察问题；本轮没有修改第三方 App，也未将统计隔离判为通过。切换连接过程中还短暂显示 A 的标题和旧内容，待 B 连接完成才更新。

精简历史通过实际服务进程的只读调试观察取证，没有修改第三方源码或响应变量。同一历史快照按一致方式编码为 UTF-8 JSON 后，完整内容为 110052 字节，精简后为 107798 字节。这个样本只证明内容确实精简，不是性能测试。精简模式下的实时审批组合未另行重测。

三台宿主共执行 21 个真实模型回合：5 个宿主接口发送的准备回合、11 个完成的手机功能回合、4 个手机取消回合、1 个模型服务拒绝回合。其中 3 个取消回合实际中断了长命令；AA 首次取消点击过晚，命令已经结束，只中止后续模型回复，因此不计为长命令取消通过。AA 随后的冷读取回合正确读回偏好，但发现首次取消已生成后续文件，没有输出附带条件的成功标记；全局记忆和取消结果分别判定。

SSH 的一次请求在调用工具前被模型服务以 HTTP 403 拒绝，当时没有审批或文件副作用。原样重试一次后正常进入待决，并在手机拒绝后停止。同 ID 的 B 会话曾尝试读取未聚焦的记忆主题，收到工具错误后改为列出主题并确认为空；没有用空默认值掩盖错误。这些中间失败不算新的产品缺陷，也不从回合统计中删除。

本轮沿用[11 月 25 日完整验收](Main-acceptance-20261125.md)中未变范围的 2143 项源码及平台结果，以及[前一轮模拟设备补验](Simulated-devices-20261126.md)中的 20 项记忆回归、类型、编译和 2 项分发结果；没有重跑这些检查，也没有重算 117 条历史回归统计。本地提交执行当前仓库配置的提交时间检查。
