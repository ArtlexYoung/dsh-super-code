### Worktree and simulator cleanup

1. Capture current disk use using the platform's disk-usage tool and run the read-only worktree audit at `../scripts/worktree-audit.sh` with the intended repository and optional base ref. The helper reports Git state; complete its rows with size, last-commit age, upstream/remote state and the current PR state through available read-only filesystem/Git/forge tools. Without an explicit base, merge state is not checked; identify the intended local base before using it. Do not fetch or treat stale local refs as current remote proof. Missing measurements or forge access stay marked unknown. Sort the report by measured size. The helper handles paths with spaces and Unicode and never removes, scans private conversations or declares a tree safe to delete.
2. Classify each worktree using its Git state plus actual task/session ownership. When public DSH session tools are unavailable, ask the user or use explicit task handoffs. Missing usage evidence means unknown, not unused. Include untracked and ignored files in the preservation decision.
3. Show the exact proposed removal paths and why each is no longer needed. Get authorization for pre-existing worktrees/data unless already covered. Keep locked, in-use, dirty or uncertain trees. A merged commit alone does not prove a directory is disposable.
4. Remove only the confirmed clean/unlocked set with normal `git worktree remove` using quoted paths. If Git refuses, inspect the reason and retain it; do not force removal or recursively erase residual files. Use the host's recoverable deletion policy for separately authorized scratch cleanup.
5. Inspect simulators and caches when they are in the requested cleanup scope. On macOS with Xcode tools, inventory normal and testing simulator sets, unavailable devices, installed runtimes, DerivedData and iOS DeviceSupport using read-only commands such as `xcrun simctl list --json`, `xcrun simctl --set testing list --json`, and `xcrun simctl runtime list`. On other systems, mark Xcode-specific items not applicable and inspect only the actual requested tools. Inventory named package caches (pnpm, uv, brew, yarn) through their own path/list interfaces. Host application caches require an explicitly identified path and scope; never infer permission to inspect private session databases, snapshots or credentials.
6. Show exact reclaim candidates, measured sizes, ownership and recovery implications. Preserve active/pinned simulators, current runtimes and retained caches. After the relevant authorization, use the owning tool's supported cleanup command, targeting specific IDs/paths; never bulk-delete all simulators or erase a user's application data as a cache shortcut. If a tool is absent or ownership unclear, retain the item and report why. This branch remains part of the workflow; lacking Xcode on a platform is not evidence that it ran.
7. Re-list worktrees, simulator/cache state and disk use. Report measured space reclaimed, removed versus retained paths/IDs and reasons. Keep audit evidence and distinguish an estimate from measured reclaimed space.
